Prototypes & OOP

Under every class in JavaScript is the same mechanism it's always had: objects linked to other objects. Understanding the prototype chain demystifies inheritance, and explains why class is "syntactic sugar" over something more flexible.

The prototype chain

Every object has an internal link — [[Prototype]], exposed as __proto__ or accessed via Object.getPrototypeOf() — to another object. Property lookup walks up this chain until it finds the property or hits null.

prototype-chain.js
const animal = {
  eats: true,
  walk() { return `${this.name} walks`; },
};

const rabbit = Object.create(animal); // rabbit's [[Prototype]] = animal
rabbit.name = "Rabbit";
rabbit.jumps = true;

rabbit.walk();          // "Rabbit walks" — found on animal, `this` is still rabbit
rabbit.eats;             // true — inherited, not own
rabbit.hasOwnProperty("eats"); // false
rabbit.hasOwnProperty("jumps"); // true

// The chain: rabbit → animal → Object.prototype → null
Object.getPrototypeOf(rabbit) === animal; // true

Constructor functions (the pre-ES6 way)

constructor-function.js
function Animal(name) {
  this.name = name;
}
// Shared methods live on the prototype — ONE copy shared by all instances,
// not duplicated per object like methods defined inside the constructor.
Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

function Dog(name) {
  Animal.call(this, name); // "borrow" the parent constructor
}
Dog.prototype = Object.create(Animal.prototype); // link the prototype chain
Dog.prototype.constructor = Dog;
Dog.prototype.speak = function () {
  return `${this.name} barks.`;
};

const rex = new Dog("Rex");
rex.speak(); // "Rex barks."
rex instanceof Dog;    // true
rex instanceof Animal; // true — Dog.prototype's chain includes Animal.prototype

class syntax

class (ES2015) is syntactic sugar over the exact mechanism above — same prototype chain, same performance characteristics, cleaner syntax.

classes.js
class Animal {
  #legs; // truly private field (ES2022) — inaccessible outside the class

  constructor(name, legs = 4) {
    this.name = name;
    this.#legs = legs;
  }
  speak() { return `${this.name} makes a sound.`; }
  get legCount() { return this.#legs; } // getter
  static create(name) { return new Animal(name); } // static factory method
}

class Dog extends Animal {
  speak() {
    return `${super.speak()} Specifically, a bark.`; // call the parent method
  }
}

const rex = new Dog("Rex");
rex.speak();       // "Rex makes a sound. Specifically, a bark."
rex.legCount;       // 4 — via the getter
rex.#legs;          // SyntaxError — private fields aren't accessible outside the class
class is not hoisted like function declarations

Classes are hoisted into the temporal dead zone, same as let/const. You cannot reference a class before its declaration line, unlike function declarations.

Composition over inheritance

Deep inheritance chains get brittle fast. Mixins — functions that return a class extending their argument — let you compose behavior instead.

mixins.js
const Serializable = Base => class extends Base {
  toJSON() { return JSON.stringify(this); }
};
const Comparable = Base => class extends Base {
  equals(other) { return JSON.stringify(this) === JSON.stringify(other); }
};

class Point { constructor(x, y) { this.x = x; this.y = y; } }
class SmartPoint extends Comparable(Serializable(Point)) {}

const p = new SmartPoint(1, 2);
p.toJSON();                     // '{"x":1,"y":2}'
p.equals(new SmartPoint(1, 2)); // true

Interview questions on this topic

Prototype-based. Even when using class syntax, objects inherit directly from other objects via the prototype chain — there's no separate "class" construct at runtime. class is sugar that makes this mechanism read more like classical OOP languages.

Object.create(proto) creates a brand-new object whose [[Prototype]] is set directly to proto — no constructor function runs. new Fn() creates an object linked to Fn.prototype and runs Fn as a constructor against it. Object.create is the more primitive operation.

Methods defined inside the constructor (this.speak = function(){}) get recreated for every single instance, wasting memory. Methods on the prototype (or defined via class, which does this automatically) are created once and shared by reference across all instances.
