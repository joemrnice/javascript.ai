Functions, Scope & Closures

Closures aren't an advanced trick — they're what happens every time a function remembers the world it was born into. Once this clicks, hooks, memoization, and module patterns all make sense.

Three ways to write a function

function-forms.js
// 1. Function declaration — hoisted entirely (name + body)
function add(a, b) { return a + b; }

// 2. Function expression — only the variable is hoisted, not the assignment
const subtract = function (a, b) { return a - b; };

// 3. Arrow function — no own `this`, `arguments`, or `super`; can't be a constructor
const multiply = (a, b) => a * b;

add(2, 3);        // works even if called above the declaration
subtract(5, 2);    // works only after this line executes
multiply(4, 5);
Why arrow functions exist

Arrow functions don't create their own this — they capture this from the enclosing scope at definition time. That makes them ideal for callbacks inside methods, and unsuitable as object methods or constructors. See the this keyword lesson for the full breakdown.

Lexical scope

JavaScript uses lexical (static) scoping: a function's access to variables is determined by where it's written in the source, not where it's called from.

lexical-scope.js
const city = "Freetown";

function outer() {
  const city = "Nairobi";
  function inner() {
    console.log(city); // "Nairobi" — resolved from where inner() was DEFINED
  }
  inner();
}

outer(); // logs "Nairobi", regardless of who calls outer() or from where

Closures

A closure is a function bundled together with references to its surrounding state — the lexical environment. That environment stays alive as long as something can still reach it, even after the outer function has returned.

counter-closure.js
function makeCounter() {
  let count = 0; // "private" — only reachable through the closure
  return {
    increment: () => ++count,
    decrement: () => --count,
    value: () => count,
  };
}

const counterA = makeCounter();
const counterB = makeCounter(); // a completely separate `count`

counterA.increment();
counterA.increment();
counterB.increment();

console.log(counterA.value()); // 2
console.log(counterB.value()); // 1 — independent closures, independent state
what's really happening Each call to makeCounter() creates a brand-new lexical environment holding its own count. The returned functions keep a live reference to that environment — this is JavaScript's native way to get private state without classes.

The classic closure-in-a-loop bug

loop-bug.js
// ❌ With var: all three callbacks share ONE function-scoped `i`
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 10); // logs 3, 3, 3
}

// ✅ With let: each iteration gets its own block-scoped `i`
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 10); // logs 0, 1, 2
}

// ✅ Pre-ES6 fix: force a new scope with an IIFE
for (var k = 0; k < 3; k++) {
  (function (captured) {
    setTimeout(() => console.log(captured), 10);
  })(k);
}

Practical uses of closures

memoize.js
function memoize(fn) {
  const cache = new Map(); // captured by the closure, invisible from outside
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

const slowSquare = n => { for (let i = 0; i < 1e6; i++); return n * n; };
const fastSquare = memoize(slowSquare);

fastSquare(9); // computed
fastSquare(9); // returned instantly from cache

arguments, rest parameters, and default parameters

parameters.js
// `arguments` — array-like, NOT available in arrow functions
function legacySum() {
  return Array.from(arguments).reduce((a, b) => a + b, 0);
}

// Rest parameters — the modern, real-array replacement
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}

// Default parameters — evaluated at call time, left to right
function greet(name = "friend", greeting = `Hello, ${name}`) {
  return greeting;
}
greet();          // "Hello, friend"
greet("Kofi");     // "Hello, Kofi"

Interview questions on this topic

Function declarations are fully hoisted — both the name and the implementation — so they can be called before their line in the source. Function expressions only hoist the variable binding (as undefined if var, or into the temporal dead zone if let/const); calling them before assignment throws.
