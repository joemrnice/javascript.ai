Variables & Data Types

Three ways to declare a variable, seven primitive types, and a coercion system that trips up even experienced developers. This is the foundation everything else sits on.

var, let, and const

var is function-scoped and hoisted with an initial value of undefined. let and const are block-scoped and hoisted into a "temporal dead zone" — they exist, but touching them before their declaration line throws.

scope.js
function scopeDemo() {
  if (true) {
    var fn = "I leak out of the block";
    let bl = "I stay inside the block";
  }
  console.log(fn); // "I leak out of the block"
  console.log(bl); // ReferenceError: bl is not defined
}

console.log(typeof neverDeclared); // "undefined" — no error
console.log(hoisted);              // undefined (not an error — var is hoisted)
var hoisted = 1;

console.log(tdz); // ReferenceError: Cannot access 'tdz' before initialization
let tdz = 2;
Rule of thumb

Default to const. Switch to let only when you know the binding will be reassigned. Avoid var in new code — it exists today purely for backward compatibility.

const prevents reassignment of the binding, not mutation of the value. This is the single most common misconception:

const-mutation.js
const user = { name: "Ada" };
user.name = "Grace";     // ✅ fine — mutating the object
user.age = 36;           // ✅ fine — adding a property
user = { name: "Linus" }; // ❌ TypeError: Assignment to constant variable.

const list = [1, 2, 3];
list.push(4);   // ✅ fine
list = [];      // ❌ TypeError

The eight data types

JavaScript has seven primitive types plus object. Primitives are immutable and compared by value; objects are compared by reference.

Spec quirk

typeof null === "object" is a bug from JavaScript's first implementation in 1995 that shipped to production and can never be fixed without breaking the web. Always check for null explicitly with value === null.

Type coercion: == vs ===

=== ("strict equality") never converts types. == ("loose equality") converts one or both operands before comparing, following the Abstract Equality Comparison algorithm.

coercion.js
0 == false;        // true  — false becomes 0
0 === false;       // false — different types, no conversion
"" == 0;           // true  — "" becomes 0
null == undefined; // true  — special-cased by spec
null === undefined;// false
NaN == NaN;        // false — NaN never equals anything, including itself
[] == false;       // true  — [] → "" → 0
[] == ![];         // true  — ![] is false, then coerced as above

Number.isNaN(NaN);      // true — the correct way to test for NaN
Object.is(NaN, NaN);    // true — Object.is fixes both NaN and -0 edge cases
Object.is(-0, 0);       // false
-0 === 0;               // true
why this matters Almost every style guide bans == for exactly this reason. Use === by default, and reach for == only for the one legitimate idiom: value == null to check for both null and undefined at once.

Truthy and falsy values

Only eight values are falsy in JavaScript. Everything else — including "0", "false", empty objects, and empty arrays — is truthy.

falsy.js
// The complete list of falsy values:
false, 0, -0, 0n, "", null, undefined, NaN

// Everything else is truthy, including:
Boolean("0");     // true — non-empty string
Boolean("false"); // true — non-empty string
Boolean([]);      // true — empty array is an object
Boolean({});      // true — empty object

Primitives vs. reference types

Primitives are copied by value. Objects (including arrays and functions) are copied by reference — assignment copies a pointer, not the data.

by-value-vs-reference.js
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 — a is untouched, b is an independent copy

const obj1 = { count: 1 };
const obj2 = obj1;
obj2.count = 2;
console.log(obj1.count); // 2 — obj1 and obj2 point to the same object

Interview questions on this topic

undefined means a variable has been declared but never assigned a value — it's the engine's default. null is an explicit assignment meaning "intentionally empty." Functions that don't return anything return undefined; a developer sets null on purpose to signal absence.

JavaScript numbers are IEEE-754 double-precision floats, which can't represent most decimal fractions exactly in binary. 0.1 + 0.2 evaluates to 0.30000000000000004. Compare with a tolerance (Math.abs(a - b) < Number.EPSILON) or work in integers (e.g. cents instead of dollars) when precision matters.

Weakly (loosely) typed, and dynamically typed. "Weak" means the engine implicitly converts between types (e.g. "5" - 1 === 4); "dynamic" means a variable's type is determined at runtime and can change. TypeScript adds static typing on top without changing JavaScript's runtime behavior.
