Modern JS & The Ecosystem

JavaScript ships new features every year via TC39, and the tooling around it moves just as fast. Here's the practical map: what changed release by release, and where TypeScript, frameworks, runtimes, and build tools actually fit.

TypeScript: what it actually adds

TypeScript is a superset of JavaScript that adds a static type system, compiled (or stripped) away before it runs. It catches a whole class of bugs — wrong argument types, typos in property names, null/undefined mistakes — before code ever executes.

types.ts
interface User {
  id: number;
  name: string;
  role?: "admin" | "member"; // optional, and constrained to a union of literals
}

function greet(user: User): string {
  return `Hi, ${user.name}`;
}

greet({ id: 1, name: "Ama" });        // ✅ compiles
greet({ id: "1", name: "Ama" });      // ❌ compile-time error: id must be a number

// Generics — reusable, type-safe across many types
function firstItem(arr: T[]): T | undefined { return arr[0]; }
firstItem([1, 2, 3]); // number | undefined
Important nuance

TypeScript's types are erased entirely at compile time — they have zero effect on runtime behavior or performance. It doesn't replace JavaScript; it compiles down to plain JavaScript that runs exactly the same as if you'd written it by hand.

React does its diffing work at runtime, in the browser, using a virtual DOM to figure out the minimal set of real DOM changes needed. Svelte does that work at build (compile) time, generating imperative DOM-update code directly — there's no virtual DOM or diffing shipped to the browser at all.

They take a graph of many small source files (and non-JS assets like CSS/images) and combine, transform, and optimize them into a smaller number of production-ready files — handling things browsers can't do natively, like JSX/TypeScript compilation, minification, tree-shaking unused code, and code-splitting for lazy loading.
