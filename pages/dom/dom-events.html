DOM & Events

The DOM is a live tree representation of the page that JavaScript can read and mutate. Events are how the browser tells your code that something happened. Together they're how JavaScript actually touches what the user sees.

Selecting elements

selecting.js
document.querySelector(".card");        // first match, any CSS selector — prefer this
document.querySelectorAll(".card");     // ALL matches — a static NodeList, not an Array
document.getElementById("app");         // fastest, ID-only lookup

// querySelectorAll returns a NodeList — use forEach directly, or spread for map/filter
document.querySelectorAll(".card").forEach(el => el.classList.add("visible"));
[...document.querySelectorAll(".card")].map(el => el.textContent);

Reading and updating content

updating.js
const el = document.querySelector("#title");

el.textContent = "New title";       // ✅ safe — treats input as plain text, no HTML parsing
el.innerHTML = "<b>New</b>"; // ⚠️ parses as HTML — XSS risk with untrusted input

el.classList.add("active");
el.classList.remove("hidden");
el.classList.toggle("open");
el.classList.contains("active"); // true

el.setAttribute("data-id", "42");
el.dataset.id;                    // "42" — dataset reads data-* attributes directly

el.style.color = "crimson";       // inline style — fine for one-offs, prefer CSS classes generally
Never innerHTML with untrusted input

If content includes anything a user typed (a comment, a search query, a URL parameter), innerHTML can execute injected <script> tags — a classic XSS (cross-site scripting) vulnerability. Use textContent, or sanitize the HTML with a trusted library first.

Creating and inserting elements

creating.js
const li = document.createElement("li");
li.textContent = "New item";
li.className = "list-item";

document.querySelector("ul").appendChild(li);   // add at the end
document.querySelector("ul").prepend(li);        // add at the start
li.remove();                                       // remove itself from the DOM

// Building a big list? Batch it with a DocumentFragment to avoid layout thrash —
// one reflow instead of one per appendChild.
const frag = document.createDocumentFragment();
items.forEach(text => {
  const li = document.createElement("li");
  li.textContent = text;
  frag.appendChild(li);
});
document.querySelector("ul").appendChild(frag); // single DOM write

Events

events.js
const button = document.querySelector("button");

function handleClick(event) {
  console.log(event.target);      // the exact element that was clicked
  console.log(event.currentTarget); // the element the listener is attached to
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick); // must pass the SAME function reference

// Preventing default browser behavior (e.g. a form submitting and reloading the page)
form.addEventListener("submit", event => {
  event.preventDefault();
  submitViaFetch();
});

Event delegation

Instead of attaching a listener to every child element, attach one listener to a shared parent and check event.target. This works for elements added later too, and uses far less memory.

delegation.js
// ❌ Doesn't scale, and misses items added after the page loads
document.querySelectorAll(".todo-item").forEach(item => {
  item.addEventListener("click", handleTodoClick);
});

// ✅ One listener on the parent, works forever — even for future items
document.querySelector(".todo-list").addEventListener("click", event => {
  const item = event.target.closest(".todo-item"); // walk up to the nearest match
  if (!item) return; // click landed on the list but not on an item
  toggleComplete(item.dataset.id);
});

Bubbling, capturing, and stopPropagation

Events travel in three phases: capture (root → target), target, and bubble (target → root). Listeners run during bubble by default.

bubbling.js
outer.addEventListener("click", () => console.log("outer"));
inner.addEventListener("click", () => console.log("inner"));
// Clicking inner logs: "inner", then "outer" — the event bubbles up

inner.addEventListener("click", event => {
  event.stopPropagation(); // stops the bubble — "outer" never logs
  console.log("inner only");
});

// Capture phase — runs BEFORE bubbling, top-down
outer.addEventListener("click", () => console.log("capture: outer"), { capture: true });

Interview questions on this topic

Attaching a single listener to a common ancestor instead of one listener per child, then identifying the actual target via event.target (usually with .closest()). It scales to any number of children, automatically covers elements added dynamically later, and uses less memory than hundreds of individual listeners.

event.target is the actual element the event originated on (e.g. the specific <li> clicked). event.currentTarget is the element the listener is attached to (e.g. the parent <ul>) — they're only the same element when there's no delegation involved.

textContent inserts a string as literal text — it's never parsed as HTML, so it can't execute a malicious <script> tag. innerHTML parses its input as markup, so inserting unsanitized user input opens the door to cross-site scripting (XSS) attacks.
