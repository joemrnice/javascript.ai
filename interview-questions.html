Interview Questions

60+ real JavaScript interview questions, organized by topic, answered the way a senior engineer would answer them out loud — not just a definition, but why it matters in practice.

Fundamentals

undefined means a variable exists (declared) but has no assigned value. Undeclared means the variable was never declared at all — referencing it throws a ReferenceError (except typeof undeclaredVar, which safely returns "undefined" without throwing).

NaN ("Not a Number") is the result of an invalid numeric operation, like 0/0 or parseInt("abc"). It's the only value in JavaScript that isn't equal to itself (NaN === NaN is false), so use Number.isNaN(value) to check for it — never value === NaN.

Before code executes, the engine scans the current scope and allocates memory for variable and function declarations. var declarations are hoisted and initialized to undefined; let/const are hoisted but left uninitialized (the "temporal dead zone") until their declaration line runs; function declarations are hoisted with their full body, so they're callable before their line in the source.

"use strict" opts into a stricter parsing and error-handling mode: it throws on assignments to undeclared variables, disallows duplicate parameter names, makes this undefined instead of the global object in plain function calls, and disallows several unsafe legacy features. ES modules and classes are strict mode by default automatically.

Synchronous code runs top to bottom, each line waiting for the previous one to finish, blocking further execution. Asynchronous code lets long-running operations (network calls, timers, file I/O) happen in the background without freezing the rest of the program, with results delivered later via callbacks, promises, or async/await.

Backtick-delimited strings supporting embedded expressions (`Hi ${name}`) and multi-line strings without escape characters. They also enable "tagged templates" — a function can intercept and transform the literal's pieces, which is how libraries like styled-components parse CSS-in-JS.

Functions & Closures

A function that takes another function as an argument, returns a function, or both. map, filter, reduce, debounce, and curry are all higher-order functions — this pattern is central to functional-style JavaScript.

An Immediately Invoked Function Expression — (function(){ ... })() — runs as soon as it's defined, creating an isolated scope. Before ES6 modules and block scoping, it was the standard way to avoid polluting the global namespace. Today it's mostly seen in bundler output and legacy code, replaced by modules and blocks.

A pure function always returns the same output for the same input and doesn't modify anything outside its own scope (no mutating arguments, no network calls, no touching global state). Side effects — logging, DOM updates, mutating a passed-in object — make code harder to test and reason about, which is why pure functions are preferred where practical.

Arrow functions have no internal [[Construct]] method and no prototype property — both of which new depends on to build a new object and link its prototype chain. Calling new on an arrow function throws a TypeError immediately.

Pre-configuring a function with some arguments to create a more specific, reusable version — e.g. turning a generic request(method, url, body) into get = curry(request)("GET"). It's common in functional composition pipelines and configuration-heavy utilities.

Non-strict mode silently creates a variable on the global object rather than throwing — a classic source of hard-to-trace bugs. Strict mode (default in modules and classes) throws a ReferenceError instead, which is one of many reasons to prefer modules.

this & OOP

Every object has an internal link to another object (its prototype). When you access a property that doesn't exist on the object itself, JavaScript walks up this chain of prototypes until it finds the property or reaches null. This is how inheritance works natively in JavaScript.

{} is shorthand for an object whose prototype is Object.prototype, inheriting methods like toString and hasOwnProperty. Object.create(null) creates an object with no prototype at all — useful as a pure dictionary/hash map with zero risk of key collisions with inherited method names.

They let a property look like a plain field from the outside while running computed logic underneath — e.g. a fullName getter that combines firstName and lastName, or a setter that validates a value before storing it. Defined with get/set in an object literal or class.

typeof returns a string naming the primitive type ("string", "number", "object", "function", etc.) — coarse-grained and doesn't distinguish object types. instanceof checks whether an object's prototype chain includes a given constructor's prototype — it answers "is this specifically an Array / a custom class / etc."

#fieldName (ES2022) creates a field genuinely inaccessible from outside the class — not just a naming convention like the old _field underscore pattern, which was always publicly accessible. It gives JavaScript real encapsulation for the first time without relying on closures or WeakMaps as a workaround.

Async & Event Loop

A race condition happens when the outcome depends on unpredictable timing between concurrent operations. A classic JS example: firing two API requests for search-as-you-type where a slower earlier request resolves after a faster later one, overwriting the correct, newer result with stale data. Fix it by tracking a request ID/AbortController and ignoring out-of-date responses.

It provides a way to cancel an in-flight async operation, most commonly a fetch request. You create an AbortController, pass its .signal to fetch, and calling .abort() rejects the fetch promise with an AbortError — essential for cancelling stale requests (e.g. when a user navigates away or types a new search query).

Yes — await works on any value. If it's not a thenable, JavaScript wraps it in Promise.resolve() automatically and resumes on the next microtask tick. await 5 is valid and simply yields 5.

A synchronous throw halts execution immediately and can be caught by any enclosing try/catch up the call stack. A rejected promise with no .catch() (or enclosing try/catch around an await) doesn't stop anything synchronously — it fires an unhandledrejection event, which in Node can even crash the process depending on configuration.

requestAnimationFrame(callback) schedules a callback to run right before the browser's next repaint, synced to the display's refresh rate (typically ~60fps) — ideal for animations. setTimeout has no relationship to the rendering cycle and can run mid-frame, causing jank in visual updates.

Arrays & Objects

Array.isArray(value) — the reliable, spec-recommended way. typeof returns "object" for arrays (unhelpful), and instanceof Array fails across different execution contexts (e.g. an array passed from an iframe).

const only prevents reassigning the variable binding — the object's properties remain fully mutable. Object.freeze() actually prevents adding, removing, or changing properties on the object itself (shallowly — nested objects are still mutable unless frozen too, so deep freezing requires a recursive helper).

Map allows any value (including objects and functions) as a key, preserves insertion order reliably, has a direct .size property, and doesn't have prototype-chain key collisions. Plain objects coerce all keys to strings and inherit properties from Object.prototype unless created with Object.create(null).

reduce(callback, initialValue) iterates the array left to right, calling callback(accumulator, currentItem, index, array) each time. The callback's return value becomes the accumulator passed into the next call. After the last item, the final accumulator is returned. Without an initialValue, the first array element is used as the starting accumulator and iteration begins at index 1.

A WeakMap holds object keys "weakly" — if there's no other reference to a key object, it can be garbage collected even while still in the WeakMap, and the entry disappears automatically. It's used for attaching private/metadata to objects (like caching computed results per DOM node) without causing memory leaks or preventing cleanup.

Modules & Ecosystem

A build-time optimization where a bundler analyzes static import/export statements to determine which exports are actually used, then removes ("shakes off") the rest from the final bundle — reducing shipped file size. It relies on ESM's static structure; it generally doesn't work reliably with CommonJS.

npm (Node Package Manager) installs, versions, and resolves dependencies listed in package.json, downloading them from the npm registry into node_modules. It also runs defined scripts (npm run build) and manages semantic versioning ranges (^/~) so projects can safely receive compatible updates.

dependencies are required at runtime in production (e.g. a UI library the app imports). devDependencies are only needed during development or build (test runners, linters, bundlers) and aren't installed when a package is installed as a dependency elsewhere with --production.

A polyfill is runtime code that implements a missing feature (like adding Array.prototype.flat to an old engine that lacks it) — it patches the environment. A transpiler like Babel rewrites your syntax at build time (e.g. converting arrow functions to regular functions) — it changes the code itself, not the runtime. Modern syntax often needs transpiling; missing APIs need polyfilling.

DOM & Browser

localStorage persists indefinitely per origin, until explicitly cleared. sessionStorage persists only for the tab's lifetime. Both store roughly 5-10MB, are synchronous, and aren't sent with HTTP requests. Cookies are much smaller (~4KB), can have expiry dates, and are automatically sent with every matching request to the server — which is why they're used for auth tokens the server needs to read.

Repeatedly interleaving DOM reads (like offsetHeight) and writes (like style.height =) in a loop forces the browser to recalculate layout synchronously on every read, instead of batching. Avoid it by reading all needed values first, then writing all changes, or by batching writes with a DocumentFragment/requestAnimationFrame.

An encapsulated DOM subtree attached to an element, with its own scoped styles and structure that don't leak in or out of the main document — the mechanism behind native <video> controls and Web Components. It prevents a component's internal markup and CSS from clashing with the rest of the page.
